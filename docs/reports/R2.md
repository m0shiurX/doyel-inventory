# R2 — data-only backup packages

Implemented a separate admin `backup.php?format=restore` download. The default SQL
export is unchanged. Restore downloads finish in a private temporary file before
attachment headers; failures return a generic reference without database errors.

`lib/backup_package.php` provides `doyel_backup_package_write(PDO, pathOrStream,
limits)`, `doyel_backup_package_read(path, optionalRowCallback, limits)`,
`doyel_backup_package_inventory(PDO)` and canonical `doyel_backup_data_encode`.
The writer opens its own repeatable-read read-only snapshot, locks expected table
metadata, asserts the complete trusted schema, collects counts/counters and business
evidence before unbuffered primary-key-ordered table cursors. Strings and NULL are
preserved without numeric casts. Customer balances use a streaming count/digest;
financial sums remain decimal strings. No business history is pruned.

The wire format is one gzip member of canonical UTF-8 JSON lines:

- Header: `kind,format,format_version,schema_version,app,snapshot_utc,timezone,
  schema_fingerprint,tables`; each table contains `columns,count,next_id`.
- Row: `kind,table,values` (values are strings or NULL in trusted column order).
- Footer: `kind,tables,payload_sha256,inventory`. Each table has row count and SHA256
  of its exact row lines. Payload SHA256 covers exact header/row lines including
  newlines, excluding the footer. The receipt also hashes the complete gzip file.
- Inventory: `financial,dates,roles,customer_balances`; balances have count/digest.

Counts in header are canonical digit strings. Footer counts are integers bounded
by the total-row limit. Next IDs are null or canonical positive strings no greater
than 2147483647, matching the current signed INT schema. Counters may be ahead of
the read snapshot due to concurrent transactions; retaining gaps is intentional.

The reader rejects noncanonical JSON, unknown structure/kinds/tables, wrong schema,
non-string fields, table order regressions, bad counts/digests, missing/duplicate
footer, trailing records, gzip truncation/CRC failure, trailing bytes and additional
gzip members. Defaults are 128 MiB compressed, 1 GiB expanded, 8 MiB per line and
10 million rows; finite positive overrides are supported. Integrity is not proof
of uploader authenticity. Reader callbacks see untrusted rows before final
verification and must target only a disposable candidate. There is no uploaded SQL
parser or execution path.

## Verification

- PHP syntax checks passed for the library, HTTP route and both CLI scripts.
- `php tests/tools/restore/package-check.php` passed exact zero/NULL/Bengali/NUL,
  large integer/fraction/exponent string preservation, 12 malformed-package cases
  and compressed/expanded/line limits.
- Native PHP 8.4 + MySQL 8.4 authorized local fixture read-only export/read passed:
  13 tables; 66,549 rows; 1,096,561 compressed bytes; 10,067,398 expanded bytes;
  measured PHP peak memory 2 MiB. No login or data mutations occurred.
- Final fixture package stayed outside the repository in `/private/tmp`; no dump,
  business rows, password hashes or credentials were committed.

`tools/restore/package-check.php` is a CLI-only verifier that outputs counts and
hashes. Parent restore integration must still test candidate insertion and exact
post-import evidence and actual Windows ACLs.

Bounded native HTTP checks passed using only the separate test-login database:
anonymous and staff requests cannot download packages; direct library HTTP access
returns 404; an administrator download passes the standalone package verifier;
the default SQL download retains DROP/CREATE and its exact completion footer.
In production, a missing configured private backup directory returns a generic
500 reference with no attachment headers or package bytes. The temporary loopback
server was stopped after testing, and HTTP artifacts remain outside the repository.
HTTP spool now uses explicit `app_config()[backup_dir]`, validated with the existing
private-directory checks; public/unwritable paths fail with a generic response.
Only non-Windows development environments may fall back to the private OS temp
directory. Windows and production require explicit owner configuration. Windows
release acceptance remains a gate: POSIX mode bits do not prove the private ACLs
that the Windows installer must provision.
