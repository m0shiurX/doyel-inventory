## Implementation

- Every owned page loads the shared bootstrap and its login guard before output;
  the AJAX/dictionary endpoints use the JSON 401 guard. SQL values are bound and
  output is escaped for its HTML/URL or JSON context. Removed APIs are absent.
- New purchase bills use the connection's inserted ID and a date-range open-bill
  lookup, serialized by the authenticated user's row. Strict inserts explicitly
  provide the old implicit values.
- Line addition locks the parent and item and writes the detail, relative stock
  increment, purchase price and parent flag in one transaction. Quantity keeps the
  legacy absolute-value behavior; the entered rate remains business input.
  Amount is computed on the server rather than trusting the readonly field.
- Removal locks the parent/detail and uses the stored item and quantity. A detail
  must belong to the selected unposted bill; its stock item is also locked and
  must exist before update/deletion. Request quantities/items cannot change stock. Repeating removal does nothing. Posted bills cannot mutate lines.
- Posting reads the stored line sum inside the parent transaction, then applies
  the entered discount. Forged readonly amount/total fields are ignored.
- Supplier dues use one query joining preaggregated purchase/expense totals,
  replacing per-supplier queries. The optional detail panel uses constant queries.
  Supplier AJAX responses retain their legacy text/HTML contract; duplicate races
  are handled without leaking SQL errors.
- Explicit text-length limits reproduce legacy truncation for expense username,
  description and remarks and purchase/supplier names under strict mode. This is
  important for the existing scenario's 25-character remarks in a VARCHAR(20).
- Dictionary endpoints return ordered JSON suggestion values. The actual purchase
  memo remains purchase-based; `PurchaseMemo.php` deliberately still displays sale
  details despite its filename, preserving its characterized behavior.

## Intentional changes and preserved behavior

Server-computed line/header amounts, stored-quantity/cross-bill-safe removal,
transactional stock updates, authentication and escaping are intentional security
and integrity changes. The hidden Posted field now reflects the real state,
fixing a legacy assignment typo. The legacy visible gross-total display is kept
for golden parity, while the stored header total includes discount.

Fractional stock arithmetic remains subject to the old integer stock column until
S3.3 converts it to DECIMAL; this slice changes no schema. Purchase rates stay
entered values. No new supplier/user interface or purchase repricing policy was
introduced.
