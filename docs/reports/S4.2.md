## Implementation and intentional behavior changes

The Accounts Data Backup link previously targeted the missing
`Backup/new_backup.php`; it now downloads from `backup.php`. The endpoint requires
an authenticated administrator. It builds the SQL entirely in PHP/PDO and names
attachments `doyel-backup-YYYY-MM-DD-HHMM.sql` in the application's Asia/Dhaka zone.
Generating the file needs no `mysqldump`, shell command, CREATE/ALTER/LOCK TABLES
privilege, or additional runtime dependency. A SELECT-only database user was
successfully tested, which is stricter than the production DML+SELECT account.

All discovered tables must be InnoDB. A repeatable-read, read-only consistent
snapshot covers every row stream; SELECT LIMIT 0 acquires table metadata locks
and every SHOW CREATE result is gathered before sending the download. Each row
SELECT is unbuffered and completely consumed/closed before the next query.
Bootstrap output buffers are discarded before streaming. INSERT batches are
limited to 200 rows or 256 KiB; an indivisible individual row may exceed the byte
limit. Memory is bounded by schema metadata, a row, and a batch, rather than the
whole table or dump. Direct PDO access here is necessary for unbuffered cursors,
quoting, and metadata APIs; identifiers come only from server metadata and are
backtick-escaped.

SQL includes SET NAMES utf8mb4, DROP TABLE IF EXISTS, SHOW CREATE definitions, and
quoted values without PHP numeric coercion. Source and restore use matching
backslash escape rules, NO_AUTO_VALUE_ON_ZERO, and UTC for TIMESTAMP values.
The dump saves/restores the destination SQL mode, time zone, and FK-check flag;
FK checks are disabled while schema/data are rebuilt. NULL remains SQL NULL.

A valid download ends with `-- Doyel backup complete.` Consumers must discard
files lacking that marker. Failures before output return generic text HTTP500
with a reference; failures after output log privately and omit the marker. The
shared S4.3 `app_errors_report()` helper is used when available, with an error-log
fallback so this slice also works before S4.3 integration. SQL streams never
receive an HTML error page or exception details, even in development mode.
