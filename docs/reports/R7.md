# R7 — owner acceptance, rollback and interrupted recovery

Implemented `lib/restore_finish.php`, `tools/restore/finish.php` and the disposable
`tools/restore/finish-check.php`. The owner module is CLI-only and is deliberately
absent from the public runtime allowlist. No production database was used.

API: `restore_finish_run(config, jobId, operation, credentials, recovery=false)`;
operation is `accept`, `rollback`, or `recover`. Four credentials are required:
current_username/current_password for the retained source administrator, and
candidate_username/candidate_password for the candidate administrator. Acceptance,
including recovery completing acceptance, additionally requires ordinary_username/
ordinary_password for a nonadministrator in the candidate. Checks use SELECT and
the existing password matcher; no password hash or business record is changed.
The native owner wrapper supplies the trusted `prepare_config_acl` callable on
Windows; no request chooses a callable, command, DB name or path.

The CLI accepts `--config=OWNER_PHP --job=32hex --operation=accept|rollback|recover`
and optional `--recover`; credentials are one bounded JSON object on STDIN.
Ordinary acceptance/rollback need a matching UI request from the last 15 minutes.
`--recover` is separate explicit owner authorization, needed when frozen HTTP
returns 503 and cannot submit another request. `operation=recover` requires it.
Credentials never enter argv, ordinary job/status files, messages or public logs.

Every operation holds the global owner lease. It verifies the sealed package,
candidate ownership, the pinned retained source, private original config bytes,
endpoint and old/new runtime identities. The authoritative config must match the
exact original hash or deterministic generated new/rollback bytes. Another job's
control is never displaced. Dedicated accounts are inspected through owner SQL:
the retained account must have exact DML; the candidate may have only SELECT or
the specifically journaled locked DML transition. Extra grants, wildcard schema
scope, aliases or uncommitted unlocked writers are refused. Generation/control
and unexpected data changes remain closed; no heuristic config guessing occurs.

After publishing frozen mode and draining the request gate, both dedicated
accounts are locked and their connections killed. READ locks cover both sets of
13 tables while separate connections compare canonical schema, every table
count/digest, counters, financial inventory and customer-balance hashes. The old
DB is checked against its verified final backup. Candidate exports are retained
and read-verified before acceptance/rollback. A pre-switch crash before the final
backup can instead make a new verified old-source export while its account is
locked, because exact original config proves the switch did not occur.

Private `owner/JOB/finish.json` records version/job, timestamp, phase and verified
candidate-export reference/hash. Acceptance phases are `accept_preparing`,
`accept_committed`, `active`. DML is granted while the candidate account remains
locked; `accept_committed` is synced **before unlocking it**. That durable marker
forbids rollback even when the public state still says awaiting_acceptance.
Recovery then completes only forward. The old account remains locked, and the
old DB, original config and pre-switch backup remain retained.

Rollback phases are `rollback_prepared`, `rollback_committed`, `rolled_back`.
The record includes the exact rollback configuration, with a generation greater
than both original and candidate generations. Its intent and candidate-export
proof precede replacement. `rollback_committed` precedes unlocking the old
account, so a later retry does not compare newly legitimate source work against
the stale pre-switch snapshot. Candidate credentials remain locked. Interrupted
precommit acceptance can revoke only the known candidate's locked DML before
rollback. No database, backup, original config or candidate export is deleted.

`recover` finishes recorded acceptance/rollback intents. Without an intent, exact
old config recovers back to the retained DB; exact new config and a SELECT-only
candidate recover to read-only awaiting_acceptance. Active/rolled-back retries
verify terminal config, both control copies, credentials and account identities
and return without freezing or rechecking stale row proofs. The ordinary job
history is extended and sanitized status republished under the owner lease.

## Verification

PHP 8.4.27 lint passed for the finish module and both CLI tools, and the R6 module
after adding owner-fixture-only subprocess checkpoints. Executed with owner
credentials on STDIN:

```
php tools/restore/finish-check.php
```

**39 assertions passed across seven isolated canonical MySQL 8.4 fixtures.**
Each used the actual R4 preparation and R6 activation contracts. Coverage includes
missing fresh approval, wrong ordinary password, unexpected candidate changes
remaining frozen, accepted DML, rollback generation, retained candidate data and
exports, post-accept rollback refusal, and terminal retries after legitimate new
data on both accepted candidate and rolled-back source.

Five real child-process exits exercised account-lock interruption before backup,
config replacement before its completion marker, acceptance after GRANT but
before commit, acceptance after its durable commit but before public active,
and rollback after config replacement. Child termination released OS/DB locks
but left persisted accounts/files for a fresh recovery call. All cases recovered
through their allowed branch. This is process interruption, not simulated
power-loss durability. Fixtures were random tiny databases/accounts and were
removed; source/client/reference databases were untouched. No full historical
dataset test was repeated (the orchestrator separately verified the user package).

Windows service stop/restart, real ACL replacement and rename behavior, HTTP
in-flight concurrency, power loss, and every possible filesystem failure remain
target/integration acceptance gates. The fixture checkpoints are gated by
owner-only `fixture=true` plus a callable and cannot be selected by a web job.
