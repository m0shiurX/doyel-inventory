## Implementation

All owned routes use the shared bootstrap and authentication guard. Queries bind
request, session and database values. Displayed text, form values and URLs are
escaped. Invalid array-shaped/string-number inputs are handled without undefined
keys or arithmetic diagnostics. Existing forms, field names, IDs, shortcuts and
page layout remain in place; report-link case is corrected.

New-bill creation serializes on the user row, finds today's open bill by a date
range, supplies strict-mode required values, and uses the connection's inserted
ID. Line addition locks the parent and item, checks the parent is unposted,
performs a guarded relative decrement, inserts the detail and updates SR in one
transaction. Catalogue SalesPrice/PurPrice determine Rate/Amt/PurAmt. Removal
locks the parent and matching detail/item, restores its stored quantity, and
removes that bill's detail in one transaction. Header posting locks the parent
and computes its amount from stored lines, minus the entered discount.

Detail rows explicitly preserve ID order. Customer options explicitly use
Nickname order: S1.1's private EXPLAIN evidence shows the legacy `SELECT Nickname`
used the covering Nickname index, so a generic primary-key fallback would change
the actual dropdown order. This is preservation, not an intended UI reorder.

Dictionary suggestions return an ordered valid JSON array consumed by the existing
JS. Item lookup retains the slash-delimited raw values and the legacy one-space
terminator. A direct business-byte comparison against the frozen endpoint passes
after removing its known PHP mysql deprecation. Auth failures return 401 before
any lookup. The sales memo uses four constant queries and keeps its visible text,
including amount words and dues, while removing its old connection/error APIs.

## Intentional changes and hand-offs

Resolved for owned files: S1/S2/S5/S7, D2, P6's open-bill lookup, F5/F7 and removed
mysql APIs. Intentional behavior changes are server-owned line/header amounts,
stored-quantity and bill-scoped removal, transactional writes/concurrency guards,
authenticated endpoints, and escaped output. Ordinary fixture flows/text match.

The stock column remains INT until S3.3. Fractional quantities can still undergo
the old stock-column rounding; a decrement rounded to no actual stock change is
not accepted as a successful guarded decrement. S3.3's planned DECIMAL(12,3)
conversion is required for exact fractional stock/reversal behavior. This slice
does not silently alter another slice's schema.

S4.1 still owns GET-to-POST/CSRF conversion for new bills, posting and removal.
S4.3 owns uniform HTTP 500/error logging for uncaught failures. Browser keyboard
and autocomplete compatibility are S4.4 acceptance checks; no browser-level
claim is made from HTTP scenarios alone. No full-modern suite is claimed here.

The verification slot is released. Port 8123 remains available for inspection;
its fixture has been reset plus 001 and only normal authentication upgraded the
admin test hash. No required S2.3 check remains blocked.
