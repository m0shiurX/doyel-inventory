## Implementation and intentional changes

All five routes bootstrap before output and use the appropriate login guard;
item search uses the JSON-style 401 guard while keeping its existing HTML row
response. SQL values are bound, displayed fields/attributes/URLs are escaped,
request arrays are handled without PHP diagnostics, and numeric values/defaults
are explicit for modern strict mode. Source-width string truncation preserves
legacy lenient imports for bounded text fields; it is performed deliberately
before writes rather than relying on the modern server to truncate silently.

List ordering is explicit. Item search retains the legacy covering `ItemName`
index order (`ORDER BY ItemName,ItemID`), confirmed by the private S1.1 EXPLAIN
entries for its source query, and still uses bound `LIKE '%term%'` and LIMIT 10.
Its `<tr><td class="re">` response contract is unchanged.

The orchestrator authorized one inventory safety fix: updating an item with the
stock field omitted now preserves its existing quantity. The admin form disables
that control, so a browser does not submit it; the old handler converted the
missing field to zero and could erase nonzero stock. New items still start at
zero. Explicit stock submissions retain the existing role/workflow semantics,
including the non-admin editable field. This slice does not invent an admin-only
stock policy or recalculate inventory from history.

Customer editing actually keeps Nickname readonly and its UPDATE never changes
it. That existing behavior is preserved, correcting the plan's generic rename
wording. The edit form now warns that historical sales/collections use nicknames
and are not rewritten by a nickname change. The warning appears only on edit.
No customer-ID migration, new rename capability or other UI feature is added.

Other legacy form quirks remain: the supplier field's first default value and
the maximum-field display behavior are not redesigned in this port.
