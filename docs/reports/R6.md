# R6 — maintenance gate and owner activation

Implemented owner-only activation to `awaiting_acceptance`; acceptance, rollback
and interrupted-state reconciliation are R7. No production operation is claimed.

`restore_dir` defaults to disabled (`''`), with DOYEL_RESTORE_DIR support.
`restore_generation` defaults to zero and is a validated nonnegative integer.
Configured deployments require owner-provisioned `published/gate.lock`: web needs
read permission, never write permission. Bootstrap holds a shared lease through
request shutdown before session/PDO work. Owner activation publishes frozen mode,
then acquires the exclusive lease to drain requests. Frozen mode and config/control
generation disagreement return generic 503. Requests queued with cached old config
fail generation comparison after a switch. Acceptance permits GET/HEAD and only
login/Restore/Report POSTs; Report POST changes session date range only. Login
hash upgrades are disabled during acceptance. Missing/different session generations
invalidate every authenticated session; successful login records the generation.
The runtime manifest includes the maintenance dependency.

`tools/restore/activate.php --config=OWNER_PHP --job=32hex` reads a JSON object
from STDIN with exactly current_username/current_password/candidate_username/
candidate_password. It prints only ID/state/generation or a generic error. No
password enters argv, public status or general journal. An untrusted fresh UI
activation request is necessary but never supplies owner authorization. Both
administrators are independently verified by SELECT and the existing password
matcher without rehashing or creating a session.

The owner runtime_config file must be outside every configured web root and all
job storage. DB environment overrides and restore-generation/root overrides are
refused. The explicit private connection must match the configured endpoint and
source DB. Production packaging must retain its trusted config.local.php stub
pointing to this authoritative private file; changing a different private file
cannot change the running application's connection.

Activation requires a dedicated runtime account: exactly USAGE and active-schema
SELECT/INSERT/UPDATE/DELETE, with no roles, global privilege or another DB grant.
Shared usernames across mysql.user entries and root identities are refused.
Database grant underscores are escaped; partial_revokes must be OFF or activation refuses before freezing. After draining, the old identity is locked
and only that username's connections are killed. A separate owner connection holds
READ locks on all 13 old and 13 candidate tables; other connections perform the
snapshot reads so transaction startup cannot release these locks. Finite metadata
and InnoDB wait timeouts fail closed. The candidate's exact schema, row digests,
next counters and business inventory are checked again against R4's sealed receipt.
A complete R2 pre-switch backup is written and read-verified before configuration
replacement. The old DB remains intact and its runtime identity remains locked.
The new random runtime account receives SELECT only throughout acceptance.

Private recovery contract, all under owner/JOB:

- `runtime-before.php` preserves exact original private config bytes (0600).
- `recovery.json` contains version/job_id, runtime_config, original_sha256,
  old_config/new_config (including runtime credentials), old_account/new_account
  ({user,host}), backup (`pre-switch.doyel.gz`), backup_sha256 (initially null),
  candidate_database, retained_database, created_at, phase and, after switching,
  new_sha256. It contains no maintenance/provisioning credential.
- `phase=prepared` is synced before freezing or any persistent DB account change.
  A crash here may have frozen control or locked the old account before the next
  marker; reconciliation must inspect actual control/config/accounts under lease.
- `old_account_locked` is recorded after account locking, before connection kills,
  candidate account creation and database READ locks. The new account may or may
  not exist after an interruption in this phase.
- `backed_up` records the complete verified backup SHA before journal switching.
- Journal `switching` precedes atomic config replacement. A crash can leave either
  config; compare authoritative file hashes rather than guessing from phase.
- `config_switched` records new_sha256 after replacement; candidate activated=true
  is also persisted. Then published acceptance/generation advances, journal becomes
  awaiting_acceptance, and recovery phase becomes `awaiting_acceptance`.
- A caught pre-switch error may restore old access only after proving exact old
  config hash unchanged, releasing DB locks and unlocking the dedicated old
  identity. It records `aborted_before_switch` and terminal rolled_back where
  applicable. After switching begins, errors never reopen writes automatically.

Atomic config writes use exclusive temporary creation in the same directory,
full writes, fflush/fsync, preserved POSIX permissions and rename without unlinking
the target. `restore_activation_config_write(path,array,?prepareAcl)` exposes an
owner-code-only callable `(temporaryPath, existingPath):void` before rename. On
Windows activation refuses before freezing unless trusted `prepare_config_acl`
exists; the writer also refuses without it. R8 must implement and verify service
read ACL preservation and service/process coordination. No web input selects a
callable or command. Config/control mismatch remains fail-closed after replacement.

## Verification

PHP lint passed for all changed PHP files. `php tools/restore/activation-check.php`
passes nine maintenance/session assertions. The same tool with `--mysql` and
owner credentials via STDIN passed **46 assertions across two isolated real MySQL
8.4 fixtures**, using actual R4 prepare/import/validation jobs and tiny synthetic
canonical data. It proved both wrong-password paths refuse before freeze; shared
request lease excludes owner exclusive lease; a READ lock blocks a second DB
connection's write; both switches reach awaiting_acceptance; all 13 pre-switch
table digests and inventories match; old generation and config/control mismatch
are rejected; old runtime login is blocked; new runtime SELECT works and UPDATE
is denied; old DB data remains readable by the owner; backup hashes and recovery
phase match. Random fixture DBs/accounts and private test artifacts were removed.
Original/source/client databases were never used by these tests.

Actual HTTP concurrency, injected process termination at every journal boundary,
Windows native ACL/rename/service restart, power-loss durability and acceptance/
rollback rehearsal remain integration gates. Pure policy assertions exercise the
mismatch window but do not constitute a process-crash rehearsal. macOS request
leases permit testing without claiming production service orchestration.
