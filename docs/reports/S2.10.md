## Integration changes

New-user creation rejects more than 30 Unicode characters before querying the
DB, displays a clear warning and adds `maxlength=30`. The server check uses a
Unicode PCRE expression, adding no extension dependency. It does not truncate
identities, edit existing users or introduce an edit-user interface. Actual local
schema inspection shows `l_user`, sales and expense UserName columns are 30
characters; purchase/collection are 50. This is friendly pre-database strict
length validation, not a claim that l_user could previously store long usernames.

Every PHP tool entry/helper now rejects non-CLI execution with an empty HTTP 404
before its normal logic. In particular the scenario runner can no longer reach
its destructive local fixture reset through the public document root. The seven
files are perf, phase1-check, characterization capture/common/compare/extract,
and scenarios/run. No public application route changed.

all 62 tracked application PHP files: 44 pages including login, six AJAX
