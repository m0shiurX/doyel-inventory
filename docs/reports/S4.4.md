Intentional behaviour changes:

- Item/supplier completion now uses plain DOM events and fetch with strict JSON parsing. Dictionary strings render as text nodes, preserving bold matching without interpreting item names as HTML.
- Completion arrows use keydown; Enter chooses the highlighted suggestion or first visible match and prevents premature implicit form submission. Existing item keyup handlers still advance to quantity/rate. Tab/Escape dismiss completion.
- Ledger completion uses `.val()` for current field contents and `.on()` for events; arrows/Enter/Escape/Tab support keyboard selection. Selection, Tab and Escape invalidate/abort pending requests so late results cannot reopen suggestions.
- Calendar controls are keyboard reachable. Opening focuses the selected day; arrows move focus, Enter/Space activate, Escape closes, and a chosen date returns focus to its field. Formatting and layout remain unchanged.
- Purchase Alt+P now follows the Post button's supplier-copy and validation path.
- Removed inline calls to undefined `dn`/`dg` functions, which had no definitions in the repository and threw while typing.
- Quantity arrows moved from keypress to keydown. Sales amount calculation now uses the current quantity when increment/decrement calls omit an argument.
- The single-item editor loads the completion script and CSS before initializing supplier completion.
