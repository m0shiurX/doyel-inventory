## Implementation and behavior

All six routes bootstrap and authenticate before output. Queries bind request,
session and database values. Displayed names, remarks, amounts, form values and
URLs are escaped; malformed array-shaped inputs do not become SQL or diagnostics.
The existing form fields, IDs, layout, amount-sign policies and workflows remain.

Payment's customer list performs one query joining pre-aggregated sales and
collections. PHP subtracts the separately fetched SUM strings and accumulates in
Nickname order, reproducing legacy floating-point display rather than changing
it through SQL arithmetic. The selected customer panel uses four additional
queries: customer, sales history, one combined dues query and payment history.
No query runs inside a customer/record rendering loop.

Customer collections retain signed admin amounts and absolute non-admin amounts.
The standalone cash/expense forms retain their existing signed-amount policy.
Cash/expense deletion was already admin-only in legacy and remains so. Payment
removal requires login/admin, preserves its alert/navigation UX, fixes the
`Payment.php` link case and halts before unauthorized mutation.

Accounts uses two fixed-table aggregate queries for all-time, current-month,
previous-month and year-to-date figures. The table loop is a fixed two-element
map, not an N+1 loop over records. Date predicates are half-open ranges. Current
periods end at tomorrow's midnight, matching the old inclusion of all of today.
Previous month now runs between actual calendar-month boundaries rather than
constructing an invalid day 31 or relying on end-of-month `strtotime` rollover.
This is a deliberate calendar-boundary correction; it is not hidden behind the
characterizer's live-period normalization. Cash in hand still includes all rows.

Text fields explicitly retain the old column-length truncation where needed for
strict-mode compatibility: expense remarks 20 characters, collection remarks
100, descriptions 100, account names 50, control codes 20 and each table's username
width. Truncation uses UTF-8 character boundaries; numeric values are never
truncated. Duplicate account heads return the old generic Error outcome without
leaking SQL; unexpected database failures remain for the global error handler.
Cash/expense tied dates explicitly use descending primary-key order, matching
the legacy date-index scan established by S1.1 EXPLAIN evidence. Account option
lists retain their original primary-key scan order.
