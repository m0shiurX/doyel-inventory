## Implementation and behavior

All three entrypoints bootstrap before output, use the intended login/admin guard,
prepared queries and escaped output. Report links use the actual lowercase folder;
the sales bill link now uses `Sales.php`. The two existing 500-row admin lists
retain their ordering and markup. They execute two queries, not per-bill queries.

Admin bill deletion locks the parent, detail rows and affected items, then reverses
stock with one aggregate UPDATE JOIN and deletes children before the header in
one `db_tx`. Sales add quantities back; purchases subtract them. It uses stored
quantities and applies to posted and unposted bills because stock changes during
line entry. Missing/repeated bill IDs are no-ops. Missing item references abort
the transaction rather than silently losing a stock adjustment. Future entry
handlers should acquire their parent lock first and item locks in ItemID order,
matching deletion. Unposting alone only changes Post, as before.

Intentional changes: non-admin unpost/delete requests halt without mutation;
admin deletes remove their detail lines and reverse stock. They no longer create
new orphans. Historical orphan cleanup remains S3.2. The existing integer stock
column still limits fractional precision until S3.3 converts it to DECIMAL; this
slice does not silently change schema or reconstruct previously rounded stock.

Stock snapshots retain access for all logged-in users. A parent INSERT and one
INSERT SELECT copy active positive-stock items atomically using `db_insert_id`.
The obsolete sales/purchase aggregate loops are removed. Report date/time inputs
are checked against exact formats and the database's supported year range;
invalid/malformed values fall back to today's date or the default boundary time.
No CSRF/POST conversion is claimed here; that remains S4.1.
