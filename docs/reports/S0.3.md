## Normalization and privacy

Tracked requests use symbolic fixture placeholders. Local read-only PDO lookups
resolve IDs/names from the database under test, including each modern slice's
DOYEL_DB_* settings. Actual name-bearing URLs/form values stay only in private
`_requests.private`; client records, cookies and diagnostic bodies are not
committed or reproduced in this report.

The extractor's single normalization table names menu titles, Report's default
date inputs, and Accounts' six wall-clock period aggregates. Historical record
dates, quantities, totals and cash-in-hand remain comparable. Dictionary suggestion
arrays compare ordered values across legacy trailing-comma syntax and the planned
JSON port; slash-delimited item lookup remains text. Hidden inputs/passwords are
not displayed text and are excluded; write-flow DB comparisons cover protocol
fields. Browser JS/CSS behavior remains S4.4's verification responsibility.

PHP diagnostics are explicitly separate from business text. The sanitized known
legacy baseline is committed in `tools/characterize/README.md`: 75 mysql-connection
deprecations, two PurchaseMemo bgcolor notices, two factory-report warnings.
Modern acceptance must still require an empty `_errors.txt`; the comparer prints
diagnostic counts without treating removal of old warnings as a business-data diff.
