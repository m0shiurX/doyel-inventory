# R3 — private restore jobs and owner-helper contract

Implemented `lib/restore_jobs.php` and CLI-only `tools/restore/jobs-check.php`.
No database, service, bootstrap, runtime config or Windows installation changes
are made by this slice. No credentials, passwords, uploaded SQL execution, shell
commands or browser-selected connection/path/database targets enter this API.

## Storage and authority

The configured absolute restore root must already exist outside the repository
and document root. Traversal segments and symlinks at any existing path component
are rejected. Owner CLI provisioning creates three fixed areas:

- `inbox`: web can create package/request/action files; owner reads untrusted input.
- `published`: owner writes sanitized status and `control.json`; web reads.
- `owner`: only owner/helper can read or write sealed packages, journals and lease.

The web-facing APIs inspect root/inbox/published only. They do not inspect or
require access to `owner`. Unix modes 0700/0600 supplement native ACL provisioning;
they do not establish a Windows service boundary. **R6 must provision and test
service-SID ACLs**, permitting web writes only to inbox, web reads to published,
and no web/LocalService owner/config/credential access. Both owner and web need
appropriate root traversal. Owner secrets and authoritative connection files
belong outside all job paths and are never part of these records.

## Procedural interface

`restore_jobs_initialize(root)` is owner CLI provisioning. The root is trusted
configuration supplied by the caller, never a browser input.

`restore_job_create_upload(root, upload, adminId, nonce)` accepts a completed,
actual PHP upload with `.doyel.gz` name. It refuses SQL with an owner-assisted
conversion message. The original name is never stored or used as a path.
`restore_job_create_local(root, source, adminId, nonce)` is the explicit CLI-only
fixture/local-owner ingestion alternative. Both return the receipt with a random
32-character lowercase hex job ID, SHA256 and actual byte count. Maximum package
size is 64 MiB compressed; R2 validates decompression, JSONL/schema and expanded
budgets. This storage layer does not claim arbitrary gzip is a valid backup.

The nonce is 32–128 lowercase hex characters; its hash is bound to the positive
admin ID. Submission locks inbox globally and reserves the nonce before a
consumable `request.json` is published. Replay returns the same receipt. Interrupted
uploads remain unconsumable and replay fails closed; a fresh upload requires a
fresh nonce. The fixed per-job package name is `backup.doyel.gz`.

`restore_jobs_claim(root)` is owner CLI only. It takes the nonblocking global
owner lease and returns null if already held or the queue is empty. Otherwise it
returns `['lease' => resource, 'job' => journal, 'directory' => sealedOwnerDir,
'package' => sealedPackagePath]`. **Retain the lease for the entire worker run**,
then `restore_jobs_release(lease)` in `finally`. Nonterminal owner jobs resume
before another candidate is claimed. Receipt/schema fields are rechecked, the
package is copied with a compressed-byte bound into the owner area, and the
sealed copy's byte count/SHA256 must match before the first journal is published.
Resume verifies the sealed package receipt again. Unknown request fields,
malformed IDs, symlinks and changed receipts fail closed. A malformed inbox entry
stops claiming rather than silently discarding evidence; owner remediation is
required. Inbox artifacts remain for audit; retention is a separate owner action.

`restore_job_transition(root,id,expected,next,evidence=[])` performs a locked
compare against the durable current state, then writes journal and public status.
Valid forward states are:

`submitted -> preflight -> creating -> importing -> validating -> ready ->
activation_requested -> frozen -> backed_up -> switching ->
awaiting_acceptance -> active`.

Failure/cancellation is allowed before switching. Owner-only transitions from
`frozen`, `backed_up` or `awaiting_acceptance` to terminal `rolled_back` record a
completed safe abort or rollback after the owner performs and verifies recovery.
`active -> rolled_back` is forbidden. An unreconciled `switching` crash retains
its state for owner reconciliation rather than claiming rollback or reopening
writers. Terminal jobs require a fresh submission to retry. Journals
contain state sequence/history and timestamps. Evidence accepts only safe opaque
`candidate_ref`, `retained_ref`, `backup_ref`, `validation_ref`, `error_ref` tokens;
no raw importer exception, row, SQL, password or credential value is accepted.
Actual owner-only candidate/config/recovery evidence is R4/R6 storage work.

`restore_job_status(root,id)` returns sanitized public status or the initial
submitted receipt while waiting for the worker. It omits admin identity/nonce.
Status publication excludes internal journal history and request fields.
Journal-before-status interruptions are repaired on the next owner claim.

`restore_job_request(root,id,operation,adminId,nonce,reauthenticated)` records only
`activation_request`, `accept` or `rollback`. The UI must supply true only after
its own fresh active-database password check, current admin authorization and
CSRF validation. It never sends plaintext passwords to jobs. Repeated action
nonces are idempotent and cannot authorize another operation.
`restore_jobs_actions(root,id)` is an owner-only reader validating exact action
fields and filename/nonce correspondence. **These web-writable requests and their
reauthenticated flag are untrusted hints, never owner authorization.** R4/R6 must
consume fixed operations under the lease, reconcile durable state, and obtain
independent offline owner approval; candidate passwords arrive through STDIN,
never argv or job storage. This slice cannot activate a database.

`restore_jobs_control_write(root,['mode'=>..., 'generation'=>int,
'active_job'=>id|null])` is owner CLI only; modes are `normal`, `frozen`,
`acceptance`. It atomically writes the owner record then a credential-free public
copy. `restore_jobs_control_read(root)` reads only that published copy. The owner
worker holds the global lease while modifying control/generation. A failed
publication fails closed and requires owner reconciliation; it never assumes
writers were frozen. R6 must integrate this control into the bootstrap and
service-drain boundary before any activation can be enabled.

Atomic JSON replacement uses exclusive temporary creation, restrictive modes,
full-write loops, fflush/fsync where available and same-directory rename. Native
filesystem rename/ACL/power-loss semantics still require Windows VM verification.
PHP does not offer an openat/O_NOFOLLOW directory-descriptor API: path checks and
opened-file inode/device checks are defense in depth; the native ACL boundary
and sealing before consumption remain essential.

## Verification

On PHP 8.4.27, `php -l lib/restore_jobs.php` succeeds and
`php tools/restore/jobs-check.php` passes 51 real-temporary-filesystem checks:
private paths, Windows separator/case comparison, traversal/symlink parents,
spoofed PHP upload, nonce/admin binding, owner-only terminal rollback transitions,
receipt integrity, exclusive worker lease, stale/invalid transitions, durable
resume, upload/seal tampering, unknown request/action headers, sanitized evidence,
action replay, control shape, bounded JSON and atomic publication refusal.
All fixture bytes live under the OS temporary directory and are removed.
No production DB or client data was read or mutated. A same-UID macOS CLI test
cannot prove Windows owner/service ACL separation, actual HTTP-upload handling,
service lifetime, power-loss durability or privileged helper deployment.
