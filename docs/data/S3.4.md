## Owner maintenance runbook

Stop application writers and invalidate active sessions for deleted IDs. Take a
full tested private DB backup as well as the row backup below. Configure the
migration database explicitly with DOYEL_DB_HOST/PORT/NAME/USER/PASS. The CLI
requires --allow-production for any connection outside isolated local fixtures;
only the owner supplies that option in production. Preview and backup paths must
be absolute and outside the repository/public root; existing output files and
symlinks are refused. POSIX, Windows drive and UNC absolute syntax use the shared
cleanup paths helper. Run PHP CLI with at least 512M memory.

```text
php -d memory_limit=512M db/cleanup/users.php --report=<private-new-preview.json>
# Review IDs, all references, history counts and private preview before applying.
php -d memory_limit=512M db/cleanup/users.php --apply=<private-preview.json> --backup=<private-new-backup.json>
# mysql: run 004_constraints.up.sql without --force, FOREIGN_KEY_CHECKS=1.
```

The CLI locks all 13 tables' records/gaps within one transaction, checks the
whole private preview against the current DB, fsyncs a mode-0600 exclusive backup
before deletion, deletes only 26/28, and verifies all survivor fields and every
history row before commit. Credentials/permissions are never merged. Drift,
unsupported pairs or dangling detail references require a new reviewed preview.
No real records or credential hashes appear in migration source or documentation.

004 adds UNIQUE(UserName) and four header/item foreign keys with explicit
ON DELETE/UPDATE RESTRICT. Existing 001 child indexes are reused. Name-based
historical references remain name-based. DDL implicitly commits; a partial DDL
failure requires inspection/recovery, not --force.

Rollback: run 004 down (constraints only), then restore the private deleted-row
backup with `php -d memory_limit=512M db/cleanup/users.php --restore=<backup.json>`.
Restore refuses another DB, any changed survivor/history state, or a still-present
username unique key; it proves all 13 tables match pre-delete state before commit.
Down alone cannot recover deleted users. Keep the full DB backup for recovery
when later writes make the strict row restore unsuitable.

Local fixture reset opt-in:

```bash
DOYEL_FIXTURES=/private/tmp/doyel-fixtures \
DOYEL_DB_MIGRATIONS=001,002,003,004 DOYEL_DB_CLEANUP_AS_OF=2026-10-28 \

```

The hook validates the complete ordered migration list and cleanup clock before
any DROP, applies cleanup after 002 and dedup after 003, then 004. Unset dedup
never deletes users; 004 then refuses unresolved duplicates.
