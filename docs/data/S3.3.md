Pre-migration local report, written before ALTER. Database `doyel_s33` uses the
original fixture with 001, 002 and approved S3.2 cleanup as-of 2026-10-28.
No production changes. Profile covers all 22 affected columns, all FLOAT/DOUBLE
columns, both nullable QT placeholders, item stock and snapshot quantities.

Targets: money extensions/header totals/cash `amount` DECIMAL(14,2); all unit
Rate/PurPrice/SalesPrice DECIMAL(14,3); Qnty/QT DECIMAL(12,3). Cash `amt` is a
nullable integer classification flag, not a monetary amount, and stays unchanged.
MinimumQuantity/MaximumQuantity remain integer thresholds. DATETIME and TEXT
capacities remain unchanged. Preserve NULL QT semantics.

All 22 target columns have zero out-of-range or meaningful excess-precision
rows. Precision uses server-rendered decimals with a 0.000001 representation
noise allowance; true half cents and fourth-decimal quantities/rates fail the
preflight. Existing three-decimal rates are real precision and are preserved.

## Write and display policy

Input normalization is exact decimal **half away from zero**: quantity to three
places, unit price to three places, money/discount to two places. Normalize before
multiplication, stock changes or total subtraction. Pure PHP decimal-string
multiplication avoids binary FLOAT and optional BCMath dependencies; SQL stock
arithmetic and header subtraction use exact DECIMAL operands. Direct, product,
stock-addition and header-total out-of-range values return HTTP 400 before writes.
Existing negative sale/return behavior and purchase absolute quantities/amounts
are preserved. Monetary cash inputs also normalize before storage.

The display formatter removes only padding (`12.300` → `12.3`); it never rounds
meaningful precision and is applied only to known numeric fields. No names,
identities, strings or IDs are passed through a global numeric coercion.

## Rollback

Down is intentionally conservative: it permits integer values representable in
the original FLOAT/INT/tinyint types and restores exact original defaults/types.
It rejects fractional values or unsupported ranges **before any ALTER**. The
actual fixture already has valid fractional history, so its down migration
refuses instead of silently losing precision. Use the tested backup for a full
fixture rollback; never round valid history to force down. A synthetic integer
schema successfully rehearsed up/down/up with original metadata restored.
MySQL8.4.13 was tested; MariaDB and Windows execution were not run.
